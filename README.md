# GEO Go

GEO Go 是一个本地运行的小工具，帮你看清 AI 怎么回答跟你品牌有关的问题，再照着结果写稿、发稿、回查。整个流程分七步：

1. **接入 AI 平台**：填上你自己的 Key。
2. **建项目**：填品牌名、别名、品类词、官网、竞品和正确的联系方式，自动生成 15 个问题。
3. **跑数**：每个问题问 N 次。
4. **诊断**：看 AI 提不提你、推荐了谁、引用了哪些网站。
5. **写稿**：按诊断结果出待办，再写品牌资料、母稿和子稿。
6. **发布**：用你自己的账号发出去，把链接贴回来。
7. **回查**：两轮结果放在一起对比，看提及率有没有变化、每篇稿有没有被 AI 引用。

数据和 Key 都只存在你自己的电脑上，不经过任何第三方服务器。

## 启动

```bash
git clone https://github.com/jinchanzi765/geo-go.git
# 国内访问慢可以用 Gitee：https://gitee.com/golden-treasured/geo-go.git
cd geo-go
node server.js          # 打开 http://localhost:3000
```

需要 Node 20 以上，不用安装任何依赖。数据存在 `./geo-data/` 目录里，这个目录不会进 git。

## 支持哪些 AI

| 平台 | 怎么接 | 说明 |
|---|---|---|
| 通义千问 | 阿里云百炼 Key | 要开联网搜索，能拿到 AI 引用了哪几条信源 |
| 豆包 | 火山方舟 Key | 要在方舟控制台开通「联网内容插件」 |
| DeepSeek | 火山方舟 Key（方舟托管的 DeepSeek 模型） | 联网搜索用的是火山的搜索，结果和 DeepSeek 官方 App 会有差别 |
| 腾讯元宝 | 暂未接入 | |

**先说清楚口径：** GEO Go 是通过接口去问 AI 的。手机 App 里的回答会受账号、地区、历史对话等因素影响，所以两边的结果会有差异。拿 GEO Go 的数据看趋势和信源够用了，如果要和手机上看到的逐条对上，就得另外做手机端监测。

## 各步状态

| 步骤 | 状态 |
|---|---|
| 1 接入 | 千问、豆包、DeepSeek 可用，元宝未接 |
| 2 建项目 | 可用 |
| 3 跑数 | 可用。并发 3，失败自动重试；欠费、未开通这类错误不重试，会直接报出来。服务重启后没跑完的轮次会接着跑 |
| 4 诊断 | 可用。包括要不要做、分平台提及率和误差范围、竞品、信源表、被引用最多的文章、AI 给错的电话 |
| 5 写稿 | 可用。仓库里只带一条示范提示词，你可以改成自己的 |
| 6 发布 | 现在要手动发，再贴链接；第 3 天去百度搜标题，登记有没有被收录。一键推送到草稿箱还在做 |
| 7 回查 | 可用 |

## 需要帮忙？

整个流程按教程一步步走，自己就能跑完。遇到下面几种情况，可以联系我们（项目维护方）：

- **想看手机 App 里的真实结果。** 接口和手机 App 的结果有差别，我们提供手机端监测。
- **想发到自己开不了号的媒体。** GEO Go 只能用你自己的账号发。新闻站、行业站这类媒体，我们有发稿渠道。
- **不想自己做了。** GEO 要连续做好几个月，监测、写稿、发稿可以全部交给我们来做：按效果交付，按月验收，不达标按合同退款。

## 用 AI 助手操作

仓库里的 `skill/SKILL.md` 是写给 AI 编程助手看的说明，比如 Claude Code。把这份文件交给它，它就知道怎么帮你启动工具、看懂诊断结果。
